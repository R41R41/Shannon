2. 提案の経路

入口と FCA 核は同じ。増えるのは ingest の planConversationTurn(envelope) だけ。遅いモデルは ingest では選ばない。

chat 即答 fast 既定 slow 実行中だけ
同じ Envelopetext / channel / 会話ID
→
Sessiondescription からカタログ行を作る
→
ターン1bind は request-tools だけ
→
本文なら完了名前が出たら次で実体を bind
→
runFcaLoopbeforeModel が tools を差し替え

Minecraft はこの経路に乗らない。遅いモデルへの上げはまだこの差分に含めていない。

3. 先頭に分類器は置かない。ターン1の bind が空に近い

判断するのは返事を書くモデル。catalogLinesForPrompt が各ツールの description 先頭行を並べる。 実装: conversationKernel.ts / Discord・Web のみ。

ターン1のモデル
本文だけ bind は request-tools と task-complete。そのまま完了。
request-tools(names) beforeModel が次ターンでその実体 + task-complete を足す。
catalogLinesForPrompt(effectiveTools) → "- google-search: Search the public web..." → プロンプトに挿す。PATH の StructuredTool.description がソース。 runConversationFca({ deferToolLoad: true, needsTools: false }) turn1 tools: [request-tools, task-complete] turn2 tools: [request-tools, ...requested, task-complete]

4. どこで何を受け取って、何を渡すか

ingest が受け取る

RequestEnvelope { channel: "discord", text: "こんにちは！元気？", conversationId: "discord:guild:ch" } // discordAdapter.toEnvelope の出力。今と同じ。

ingest が渡す（新規）

ConversationPlan { lane: "chat", model: "claude-haiku-4-5", toolNames: [], policy: { kind: "text" }, maxTurns: 1, allowEscalate: false }

Session が FCA 核へ渡す（chat）

runFcaLoop({ model: haiku, tools: [], policy: { kind: "text" }, limits: { maxTurns: 1 } }) // 1回話して終わり。task-complete も強制しない。

Session が FCA 核へ渡す（fast）

runFcaLoop({ model: haiku, tools: [search, weather, fetch, history], policy: { kind: "terminal-tool", name: "task-complete" }, needsTools: false }) // 道具未使用でも終われる。必須にしない。

# S2「体：ネザー奥・パール・要塞探し」の体の部品（2026-11-02）

エンドラ討伐スプリントの S2。ブレイズ・エンダーマン・物々交換・目玉の飛び・枠探し・ネザーの移動の部品。判断は頭の LLM、体は頼まれた目的をやり切る。
先例の mine-ai-mcp（aibengineering、MIT）は読んで学び、コードは書き直した（各ファイルの先頭に方法の出どころを書いている）。
数字は全て PC の WSL ラボ（隔離サーバー・自然世界 c2〜c7・LLM 無し・本番に触れない）の実測。どれも一回きりの標本で、少ない所は少ないと書いた。

## 1. 頭が読む物・変わった物

小さな共通の直し：`findEntity`（種類名で相手を探す所）は、死に際で体力 0 の個体を飛ばす（倒した直後の死体を「最寄りの blaze」にして「見えなくなった」と返していた）。`place` は `warped_roots`・`crimson_roots`・`nether_sprouts`・`hanging_roots` を「ブロックが取って代われる物」に数える（ゲームの通り。ネザーの森の床はこれで覆われている）。

### `ActResult.eye`（既存の 5 欄は同じ。足したのは任意の欄）
```
eye: { from, bearingDeg, flew, to, broke,                     // 既存（契約）。bearingDeg は小数 2 桁、broke は「割れる合図を見た」
       origin:{x,y,z},      // 投げた時の体の足の位置（正確な小数）。線の始点はここ
       unit:{x,z},          // 水平の単位ベクトル（x 東・z 南）。bearingDeg と同じ向き。down の時は null
       start, end:{x,y,z},  // 目玉の最初と最後の位置
       rise,                // end.y - start.y（上が正）
       fate:'dropped'|'shattered'|'unknown',   // 接続の言葉で見た終わり方（落ちた＝ender_eye の item が出た、割れた＝level event 2003）
       drop?:{id, at:{x,y,z}},                 // 落ちた時。pickup target=<id> で拾える
       arrived: boolean,    // 飛びが 11.9 ブロック未満で止まった＝要塞が 12 ブロック以内で、終点（end）の x・z が要塞の起点（/locate が指す所）。実測 6 回で終点のずれ 0.3 ブロック以内。12.0 ちょうど飛んで上 8.1 なら false（遠い）
       samples, ms,         // 見た位置の数・ミリ秒
       down?: true }        // 横に 1 ブロック未満で沈んだ＝要塞は真下（このとき bearingDeg は 0 で意味が無い）
```
- 旧の `broke` は「目玉の entity が消えて持ち物が減った」なら常に真だった（投げれば必ず減る）。今は割れる合図を見た時だけ真。
- 行は 160 字で切られるので、方位・水平距離・上・向き・終わり方を先頭に置いた。細かい数字は `eye` にある。
- **目玉が指すのは要塞の「起点」（`/locate` が言う x・z）で、エンドポータルの間ではない。** 実測の世界ではポータルの間が起点から 54 ブロック離れていた。起点に着いたら `find-structure stronghold` の枠探しをする（§1 下）。

### `find-structure`（skill。args と種類を足しただけ）
**`structureType=stronghold`** は **エンドポータルの枠だけ**を探す（感染した石レンガは「要塞が近い」印としてだけ言う）。任意の `radius`（16〜128、既定 64）、`x`・`z`（探す中心、既定は今いる所）。
高さは問わず、中心から水平に半径内の枠を近い順に最大 12 個。無ければ、16 ブロック刻みの輪（16・32 … 半径まで、各輪の点は 16 ブロック間隔）の「次に歩く点」を、前の呼び出しで読み込みが届いた所を除いて返す。歩いて着いたらもう一度呼ぶ。

**`structureType=blaze_spawner`**（新）はネザーの読み込み済みの範囲の湧き場（`spawner`）と、その 3 ブロック以内の**野営向きの足場**を最大 4 つ返す：床があり頭上 2 マスが空き、**縁が無い**（開いた側の隣の床が 1 段より下がらない）、火・溶岩・マグマの中や隣でない。3 マス先までに深い穴へ続く側が少ない順、壁の面が多い順、湧き場から 2 マスに近い順。湧き場の 5 マス内の火の数も言う。実機の出力：
```
ブレイズの湧き場を発見: (-101, 56, -115)、距離4m（ほかに (-88, 56, -165) 47m）。野営向きの足場（湧き場から3m以内・縁なし・火なし。壁が多い順）: (-103, 56, -116) 2.2m・壁2面 / (-99, 56, -116) 2.2m・壁2面 / (-103, 56, -113) 2.8m・壁2面 / (-99, 56, -113) 2.8m・壁2面。そこへ go で着いてから attack hold か fight（…）
```
理由：実機の要塞では、ラボが staged した「立つ場所」が**穴の縁の 1 マス幅の足場**で、そこと部屋の北の入口で体が 3 マス下の穴に落ち、ブロックが無く戻れなかった（2 回。押されたのか反射で動いたのかは未確認）。

## 2. エンダーマン：屋根の穴
- 先例は怒らせてから屋根を作る。ここでは**屋根を先に作る**：怒ったエンダーマンは 1〜2 秒で届き、1 撃は 7 点と押し出しで、9 ブロックは約 2 秒かかる。遠い（3 ブロック以上）相手の目への視線は屋根の縁の下を通るので、穴の中から目を見て怒らせられる。ブロックは次のエンダーマンのために残る。
- 屋根の形：体の足のマス `c` に対し、`c` と周りの 8 マスの上（足 +2）に 3×3。2 マスの高さではエンダーマン（高さ 2.9）は立てず、立てる一番近い所は 2 マス先で、中心間 1.8 > 1.43（敵の攻撃の届き：箱を 0.83 広げた分）。周りに低い穴があれば床を埋める。最初の 1 個を当てる支えの柱は、エンダーマンと反対側に作る。普通の平地で 11 個（支え 2 ＋ 屋根 9）。
- 怒らせる：頭の高さ 2.55 の目を見る（サーバーの測り：視線と目への線の内積 > 1 − 0.025/距離、線が通っている）。床の `gazeGuard` は視線をずらすので、見つめる間だけ外して戻す。怒った後は目を見ない（4 ブロック内で見ると瞬間移動で逃げる）。弓は使わない。
- 場所：立っている所に屋根が作れない（隣の 1 段下がりを埋められない等）時は、半径 7 マスで計画が成り立つ所（ブロックが少なく近い順）へ歩いて、そこで始める（行に「屋根を作れる所 (x,y,z) へ N m 歩いた」）。屋根の縁の死角（約 3.7 ブロック以内）や支えの柱で目が見えない間は 8 秒待つ（動くので）。
- 直した別の穴：`fight` は `creeperLit`（データ枠 16・18 を種類を見ずに読む）で「点火したクリーパー」と判定していたが、エンダーマンの `stared_at`（枠 18）が真になると体が穴から走り出した。種類を見るようにした。

## 3. ブレイズ：先例の失敗を避ける形と、実機で分かったこと
- 「ロッド 1 本で火の反射が体を取った」：撃たれて燃えた体を床の「燃えて射手から見えている時に射線を切る」反射が連れ出した。叩く瞬間（盾を下げる 1 打撃と、盾が効くまでの 5 tick）にしか火の玉は当たらないので、火の玉が着く直前と撃つ直前は叩かない。
- 「6 本で盾が 2 枚壊れた」：盾は止めた火の玉 1 個で 6 すり減る（336）。体の側では防げない。**実機では 25 秒に 72（12 発）、湧き場の部屋の中では 87 秒で 174**。湧き場に長く立たない・撃つ体を減らす・盾の予備と火炎耐性が頭の側の知識。盾の傷みは行に出る（「盾 −N（残り M）」）。壊れたら荷の予備に替える（`fight`・`attack hold` とも）。
- ブレイズの AI（バニラの `BlazeAttackGoal` の記憶による読み。実機では 4〜5 マスで浮いたままの個体が多かった）：見えていて 2 マス以上離れている間はその場に浮いて撃ち、近づくのは 2 マス未満（近接）か見えない時だけ。だから待つだけの `hold` は、湧いた瞬間に 3 マス内にいた個体しか打てないと読める。`fight`（3.5 マスの紐付きで近づく）のほうが倒せる。
- 火：火の玉は着いた面の隣に火を置く。ネザーラック・レンガの湧き場では燃え続け、体の足元が燃えると床の `lava_escape` 反射が体を連れ出して手が止まる。`go` は火の中と隣を行き先にしない（`unsafe`）ので、頭は足場を探し直すか火を消す。火炎耐性があれば火の玉の5点も炎も無効（ゲームの規則。実機は未確認）。

## 4. ネザーの移動
- ソウルサンドは歩幅 40%＝時間 2.5 倍。経路探索の 1 歩の費用を +1.5（`exclusionAreasStep`）。回り道が少し長いだけなら避け、他に道が無ければ渡る。`go` もこの上に乗っている。
- 溶岩の縁（`lavaBesideStepCost` = 8）・ガストの火の玉の打ち返し・縁の止まりは既存のまま。

## 7. 頭の契約に要る変更（S3・S0 へ）
- act の手の種類・欄は増やしていない。行の言葉が増えた（上の表）。`ActResult.eye` に任意の欄が増え、`broke` の意味が変わった（上）。
- `find-structure` の description と args（radius・x・z、`blaze_spawner`）が変わった → **catalog.json の description とハッシュは S0 が録り直す**。
- `fight enderman` は体が持つ建築用ブロックを使う（canPlace 不要）。

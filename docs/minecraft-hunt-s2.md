# S2「体：ネザー奥・パール・要塞探し」の体の部品（2026-11-02）

エンドラ討伐スプリントの S2。ブレイズ・エンダーマン・物々交換・目玉の飛び・枠探し・ネザーの移動の部品。判断は頭の LLM、体は頼まれた目的をやり切る。
先例の mine-ai-mcp（aibengineering、MIT）は読んで学び、コードは書き直した（各ファイルの先頭に方法の出どころを書いている）。
数字は全て PC の WSL ラボ（隔離サーバー・自然世界 c2〜c7・LLM 無し・本番に触れない）の実測。どれも一回きりの標本で、少ない所は少ないと書いた。

小さな共通の直し：`findEntity`（種類名で相手を探す所）は、死に際で体力 0 の個体を飛ばす（倒した直後の死体を「最寄りの blaze」にして「見えなくなった」と返していた）。`place` は `warped_roots`・`crimson_roots`・`nether_sprouts`・`hanging_roots` を「ブロックが取って代われる物」に数える（ゲームの通り。ネザーの森の床はこれで覆われている）。

### `ActResult.eye`（既存の 5 欄は同じ。足したのは任意の欄）
```
eye: { from, bearingDeg, flew, to, broke,                     // 既存（契約）。bearingDeg は小数 2 桁、broke は「割れる合図を見た」
       origin:{x,y,z},      // 投げた時の体の足の位置（正確な小数）。線の始点はここ
       unit:{x,z},          // 水平の単位ベクトル（x 東・z 南）。bearingDeg と同じ向き。down の時は null
       start, end:{x,y,z},  // 目玉の最初と最後の位置
       rise,                // end.y - start.y（上が正）
       fate:'dropped'|'shattered'|'unknown',   // 接続の言葉で見た終わり方（落ちた＝ender_eye の item が出た、割れた＝level event 2003）
       drop?:{id, at:{x,y,z}},                 // 落ちた時。pickup target=<id> で拾える
       arrived: boolean,    // 飛びが 11.9 ブロック未満で止まった＝要塞が 12 ブロック以内で、終点（end）の x・z が要塞の起点（/locate が指す所）。実測 6 回で終点のずれ 0.3 ブロック以内。12.0 ちょうど飛んで上 8.1 なら false（遠い）
       samples, ms,         // 見た位置の数・ミリ秒
       down?: true }        // 横に 1 ブロック未満で沈んだ＝要塞は真下（このとき bearingDeg は 0 で意味が無い）
```
- 旧の `broke` は「目玉の entity が消えて持ち物が減った」なら常に真だった（投げれば必ず減る）。今は割れる合図を見た時だけ真。
- 行は 160 字で切られるので、方位・水平距離・上・向き・終わり方を先頭に置いた。細かい数字は `eye` にある。
- **目玉が指すのは要塞の「起点」（`/locate` が言う x・z）で、エンドポータルの間ではない。** 実測の 5 世界で起点→ポータルの間は 7・47・51・54・72 ブロック、向きはばらばら（枠探しの半径は 128 が要る）。起点に着いたら `find-structure stronghold` の枠探しをする（§1 下）。

### `find-structure`（skill。args と種類を足しただけ）
**`structureType=stronghold`** は **エンドポータルの枠だけ**を探す（感染した石レンガは「要塞が近い」印としてだけ言う）。任意の `radius`（16〜128、既定 64）、`x`・`z`（探す中心、既定は今いる所）。
高さは問わず、中心から水平に半径内の枠を近い順に最大 12 個。無ければ、16 ブロック刻みの輪（16・32 … 半径まで、各輪の点は 16 ブロック間隔）の「次に歩く点」を、前の呼び出しで読み込みが届いた所を除いて返す。歩いて着いたらもう一度呼ぶ。

**`structureType=blaze_spawner`**（新）はネザーの読み込み済みの範囲の湧き場（`spawner`）と、その 3 ブロック以内の**野営向きの足場**を最大 4 つ返す：床があり頭上 2 マスが空き、**縁が無い**（開いた側の隣の床が 1 段より下がらない）、火・溶岩・マグマの中や隣でない。3 マス先までに深い穴へ続く側が少ない順、壁の面が多い順、湧き場から 2 マスに近い順。湧き場の 5 マス内の火の数も言う。**隠れ場所**（2026-11-03 追加）も最大 3 つ、野営マスから歩数つきで言う：湧き場のブレイズが居うる所（湧き場の周り ±4 マス・高さ −1〜+3 の 100 点のうち岩の中でない所）のどこからも、体の目と胸への線が通らない足場。歩ける所を幅優先で 40 歩まで探す（1 歩は 1 マス横か 1 段の上り下り）。柵・階段・半ブロック・格子は線を通すので隠れ場所にならない。c1 の湧き場 (140,77,75) では野営マス (141,77,73) から **17 歩・東へ 13m・3 段下の (154,74,77)**（南へ伸びる 3 幅の廊下。橋の上の見え方は東へ行くほど減る）、c1 のもう一つの湧き場 (202,83,62) では 12 歩の (190,81,61)。実機の出力：
```
ブレイズの湧き場を発見: (-101, 56, -115)、距離4m（ほかに (-88, 56, -165) 47m）。野営向きの足場（湧き場から3m以内・縁なし・火なし。壁が多い順）: (-103, 56, -116) 2.2m・壁2面 / (-99, 56, -116) 2.2m・壁2面 / (-103, 56, -113) 2.8m・壁2面 / (-99, 56, -113) 2.8m・壁2面。そこへ go で着いてから attack hold か fight（…）
```
**`probe kind=frames` / `kind=camp`**（新。LLM-centric の V2 は catalog の skill を呼べず `act` と `probe` だけなので、同じ関数を probe からも言う。`utils/huntStructures.ts`）：`frames` は x・z（探す中心）・radius（ブロック 16〜128、既定 64）で、枠の座標と目の有無（`found`）か、無ければ輪の次の点（`next`）。`camp` はネザーの湧き場と野営向きの足場と隠れ場所（`spawner`・`cells`・`fire`・`hideouts`）。答えは契約どおり `{ v:1, kind, text, … }` で文が先頭。実機で `find-structure` と同じ文が返ることを確かめた（camp 4 足場・frames 12/12）。

理由：実機の要塞では、ラボが staged した「立つ場所」が**穴の縁の 1 マス幅の足場**で、そこと部屋の北の入口で体が 3 マス下の穴に落ち、ブロックが無く戻れなかった（2 回。押されたのか反射で動いたのかは未確認）。

## 2. エンダーマン：屋根の穴
- 先例は怒らせてから屋根を作る。ここでは**屋根を先に作る**：怒ったエンダーマンは 1〜2 秒で届き、1 撃は 7 点と押し出しで、9 ブロックは約 2 秒かかる。遠い（3 ブロック以上）相手の目への視線は屋根の縁の下を通るので、穴の中から目を見て怒らせられる。ブロックは次のエンダーマンのために残る。
- 屋根の形：体の足のマス `c` に対し、`c` と周りの 8 マスの上（足 +2）に 3×3。2 マスの高さではエンダーマン（高さ 2.9）は立てず、立てる一番近い所は 2 マス先で、中心間 1.8 > 1.43（敵の攻撃の届き：箱を 0.83 広げた分）。周りに低い穴があれば床を埋める。最初の 1 個を当てる支えの柱は、エンダーマンと反対側に作る。普通の平地で 11 個（支え 2 ＋ 屋根 9）。
- 怒らせる：頭の高さ 2.55 の目を見る（サーバーの測り：視線と目への線の内積 > 1 − 0.025/距離、線が通っている）。床の `gazeGuard` は視線をずらすので、見つめる間だけ外して戻す。怒った後は目を見ない（4 ブロック内で見ると瞬間移動で逃げる）。弓は使わない。
- 場所：立っている所に屋根が作れない（隣の 1 段下がりを埋められない等）時は、半径 7 マスで計画が成り立つ所（ブロックが少なく近い順）へ歩いて、そこで始める（行に「屋根を作れる所 (x,y,z) へ N m 歩いた」）。屋根の縁の死角（約 3.7 ブロック以内）や支えの柱で目が見えない間は 8 秒待つ（動くので）。
- 直した別の穴：`fight` は `creeperLit`（データ枠 16・18 を種類を見ずに読む）で「点火したクリーパー」と判定していたが、エンダーマンの `stared_at`（枠 18）が真になると体が穴から走り出した。種類を見るようにした。

## 3. ブレイズ：先例の失敗を避ける形と、実機で分かったこと
- 「ロッド 1 本で火の反射が体を取った」：撃たれて燃えた体を床の「燃えて射手から見えている時に射線を切る」反射が連れ出した。叩く瞬間（盾を下げる 1 打撃と、盾が効くまでの 5 tick）にしか火の玉は当たらないので、火の玉が着く直前と撃つ直前は叩かない。
- 「6 本で盾が 2 枚壊れた」：盾は止めた火の玉 1 個で 6 すり減る（336）。体の側では防げない。**実機では 25 秒に 72（12 発）、湧き場の部屋の中では 87 秒で 174**。湧き場に長く立たない・撃つ体を減らす・盾の予備と火炎耐性が頭の側の知識。盾の傷みは行に出る（「盾 −N（残り M）」）。壊れたら荷の予備に替える（`fight`・`attack hold` とも）。
- **湧き場の足場にいる間は、全部の act に `accept: ["blaze"]` を付ける**（dig で火を消す・go・eat・pickup だけの act にも）：S4 の c1 の試験（`hunt-s4-c1-headhold2`）で、dig だけの act の間に床の反射「燃えて射手から見えている時に射線を切る」が体を取り、**足元の床を掘って下がった**（『足元を掘って下がった (141,76,73)。まだ見えている: blaze #554 上4・5.9m』）ため足場が宙になり、体が 7 段落ちて 8 回続けて go が止まった。その反射は、act の `accept` が blaze（か fight/attack の手が走っている間）なら体力が高い間は体を取らない（`llmcR7Body.test.ts`：体力 18 では取らず 7 では取る）。1 段の穴は上に浮く blaze から隠れない。足場を失った時は荷の丸石で `go`（canPlace）で戻す。
- ブレイズの AI（バニラの `BlazeAttackGoal` の記憶による読み。実機では 4〜5 マスで浮いたままの個体が多かった）：見えていて 2 マス以上離れている間はその場に浮いて撃ち、近づくのは 2 マス未満（近接）か見えない時だけ。だから待つだけの `hold` は、湧いた瞬間に 3 マス内にいた個体しか打てないと読める。`fight`（3.5 マスの紐付きで近づく）のほうが倒せる。
- 火：火の玉は着いた面の隣に火を置く。ネザーラック・レンガの湧き場では燃え続け、体の足元が燃えると床の `lava_escape` 反射が体を連れ出して手が止まる。`go` は火の中と隣を行き先にしない（`unsafe`）。**火は `dig` で消せる**（実機：`dig at [火のマス]` が 0.2 秒で「fire を掘った」、そのあと air）ので、`unsafe` の行は火のマスと「dig で消せる」を言う（例：`行き先 (-102,120,-120) は fire の隣… 火 (-101,120,-120) は dig で消せる。または別の行き先を`）。火炎耐性があれば火の玉の5点も炎も無効（ゲームの規則。実機は未確認）。

## 3b. c1 の湧き場（本番のシードの要塞）の実機：体の安全の測りと、頭の出撃の形（2026-11-03）

場所：c1（本番の実走のシード）の湧き場 A (140,77,75)。部屋は 5×5（x 138〜142・z 73〜77）で、北・西・南に壁があり、**東（x=143、z 74〜76）が開いて下りの階段**（(143,76)→(143,75)）が、東へ伸びる 3 幅の橋（y=74、z 74〜76）に続く。橋の途中 (154,74,77) から**南へ 3 幅の廊下**（x 153〜155、z 77〜84）が伸び、そこは湧き場のどの浮き場所からも見えない（見え方 0）。部屋の中はどのマスも湧き場の浮き場所の約 8 割から見える。もう一つの湧き場 B (202,83,62) は岩の中の部屋で、西側が低い見え方の広間に続き、隠れ場所は 12 歩の (190,81,61)。

### 測り方
LLM 無し。台本の「頭」が `mc_probe kind=camp` の答え（野営マス `cells[0]`・隠れ場所 `hideouts[0]`）だけで動く。頭の判断の間は 5 秒の待ち（S3 の測り：判断は約 4〜5 秒）。装備は鉄の防具・盾 2・ダイヤの剣・鉄のツルハシ・丸石 64・調理済み牛肉 24・金のリンゴ 3。difficulty normal・夜。各場面は 1 回きりの標本（N が小さい）。HUNT_KEEP の黒箱で止まりの前の 90 秒を読んだ。

### 分かったこと（体の側の事実）
1. **湧き場の部屋は 6 体にすぐ満ちる**（60〜90 秒）。野営マス（湧き場から 2.2m）は湧き場の出現箱（±4）の中なので、湧いた個体が体の 0.5〜2m に出る。6 体に囲まれると 5〜10 秒で体力が 16→0 になった（死亡 3 回の記録は下）。
2. **頭の判断の間（約 5 秒）に体を野営マスに置いておくと、火の玉 2 発（体力 6.24）を受けた**（2 場面で同じ 6.24）。act の外に体を湧き場の見える所に置かない。
3. **hold は体力は保つが盾を食う**：S4 の c1（`headhold2`）の 25 秒 4 回で体力 20 のまま・盾 −48／−72／−60／−90（4 回で 270＝336 の 8 割）・撃破 1・ロッド 0。fight は撃破が速いが 1 回に 10〜20 受ける（S4・私の実測）。
4. **火**：火の玉が野営マスの足元・頭の上に火を置き、`lava_escape` の反射が体を野営マスから出して act を止める（5 場面で何度も）。→ 体が自分の足元・頭の火を dig で消す（下、実機で確認）。
5. **低体力の床の反射**（体力 8 未満の逃走・足元を掘る・食べる）は、橋を東へ走る間も湧き場の見える所で、掘る・食べる間は盾が使えず、遠い（12〜25m）blaze 1 体に撃たれて 0.4 まで落ちて死んだ（pb1 の 1 場面）。

6. **床の反射の連鎖が死因になった**：体力 8 未満で、cover（1 回に 3 段）と last stand（1.5 秒に 1 段、上限なし）が合わせて**橋の下へ 6 段の縦穴**（(148,75,77)→(148,70,77)）を 10 秒で掘り、blaze の押しで落ちて y 52 で死亡（25 秒の出撃の場面。別の場面は隠れ場所の廊下で「12m 先の blaze が届く」と読んで 7 回掘り、後の出撃がその穴から始まって橋から落ちた）。直した：床の掘り下げは cover と last stand を合わせて 30 秒に 3 回まで、見えない blaze・ghast（6m より遠い）は逃走・last stand の脅威に数えない。
7. **火**：体が足元・頭の火を dig で消すようにした（実機 4 回：火は約 0.1 秒で消え、反射の出番 0・体は動かず・体力減 0）。ツルハシが荷に無い時の last stand は、掘れない足元（nether_bricks）の dig を選ばない。

## 4. ネザーの移動
- ソウルサンドは歩幅 40%＝時間 2.5 倍。経路探索の 1 歩の費用を +1.5（`exclusionAreasStep`）。回り道が少し長いだけなら避け、他に道が無ければ渡る。`go` もこの上に乗っている。
- 溶岩の縁（`lavaBesideStepCost` = 8）・ガストの火の玉の打ち返し・縁の止まりは既存のまま。
- **実機の長い歩き（c2、玄武岩のデルタを通る 176 ブロック、`go to` 要塞の立ち位置、鉄のつるはし 1 本・丸石 64、`canDig`＝netherrack・basalt・blackstone、`maxDig 120`・`maxPlace 40`・`seconds 100`、止まるたびに同じ手をもう一度）**：7 回の手で **286 秒、125 ブロックまで**（残り 51）、体力減 0、死亡 0。1 回ごとの止まり方は行がどれも次を言っていた：
  ①24.7 秒で (-7,42,-7) の**マグマブロックの上**（降りた先）に立ち「溶岩回避の反射が始まった」で手が止まった（反射は 0.3 秒でマグマから離れた）→同じ手をもう一度で進んだ。
  ②85.8 秒（道 106 歩・掘 68・置 26）で `limit_place`「置く所が 15 あり上限 40 の残り 14 を超える」→③10 秒で `low_floor`（足元が空気で積む土台が無い。「丸ごとの床の所へ動いてから登る」）→④100 秒（掘 105・置 28）で `limit_dig` →⑤**45 秒で `tool_broke`（鉄のつるはし 1 本が約 250 回掘って壊れた）**→⑥⑦要塞の床（nether_bricks）が頭の上に来て `dead_end`「掘ってよい物に無い。canDig に足すか、別の場所から」。

## 7. 頭の契約に要る変更（S3・S0 へ）
- act の手の種類・欄は増やしていない。行の言葉が増えた（上の表）。`ActResult.eye` に任意の欄が増え、`broke` の意味が変わった（上）。
- `find-structure` の description と args（radius・x・z、`blaze_spawner`）が変わった → **catalog.json の description とハッシュは S0 が録り直す**。
- `fight enderman` は体が持つ建築用ブロックを使う（canPlace 不要）。
- `probe` の kind に `frames`・`camp` が増えた（`PROBE_KINDS`・description）→ catalog の再録も S0。
- 当日は人の手が入らないので、失敗の行に「次に試せること」を足した（物々交換・屋根・見えない相手の行）。
- 道（ネザーの長い歩き）の止まり行の言葉：`go` は火の隣の行き先を断る時に火のマスと「dig で消せる」を言い、置く物が尽きた時は `not_loaded` などの行に「置く物 … を N 個置いて使い切った」を足し、`no_blocks` では荷にある安い置ける物（netherrack・basalt・dirt など。鉱石・黒曜石・板材は言わない）を名指しする。道具が壊れて予備が無い時の act の行は「道具が壊れて止まった（同じ種類以上の予備が荷に無い）。作るか拾って持ってから、同じ手をもう一度」（以前は「命令が止められた（tool_broke）」）。`probe kind=camp` の「湧き場が無い」の文は `find-structure` でなく `probe kind=scan` の「ネザー要塞」の向きを指す。契約の欄・コードは同じ。
- `fight` が相手を 32 m 内に見つけられない時（`lost`）の行が、種類ごとの次の手を言う：blaze は「湧き場の部屋が見える足場（probe kind=camp）へ go で寄り、blaze が見えてから呼ぶ。居ない時は少し待つ」、enderman は「開けた所へ動いて probe kind=around で居る所を確かめ、見える所で呼ぶ」（S4 の c1 の試験で、頭が湧き場のかごの陰の blaze に 3 回続けて呼んで「見えない」だけを返されていた）。
- 頭の知識（S3）：ネザーの歩きは `canDig`＝[netherrack,basalt,blackstone]（要塞の中は nether_bricks も）、`canPlace`＝[cobblestone,netherrack]、`maxDig` 120→200、`maxPlace` 40→100、`seconds` 100〜120、鉄のつるはし 3 本以上、止まったら行の言う通りに直して同じ go をもう一度（§4）。
- 壁の中に閉じ込められた体の「壁抜け」反射（`wallReflex.ts`）の時間切れを 10 秒から 25 秒にした：道具なしで丸石を素手で掘ると 10 秒かかり、以前は毎回掘り終える直前に切れて、90 秒で体力が 20→1 になった（ラボで再現）。道具があれば掘りは 1 秒ほどで、変わらない。

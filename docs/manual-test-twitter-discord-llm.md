# Twitter / Discord / LLM 手動テストチェックリスト

LLM やアダプタ改修のあと、**画面とログを見ながら**退行がないか確認するとき用の作業リストです。  
自動テスト（`backend/tests/unit/adapters/`・`backend/tests/unit/routes/twitterWebhook.test.ts`）は HTTP・Envelope 変換・Webhook 分岐まで。ここでは **実サービス・実会話** の観点を扱います。

---

## 使い方

- 改修範囲に応じてセクションをスキップしてよい。
- 各項目は **□** をチェックし、問題があれば「日付・再現手順・ログ行・スクショ」をメモする。
- 本番相当で危険な操作（実アカウントへの大量返信など）は **ステージング／テスト用 Bot** で実施する。

---

## 0. 事前準備

| 作業 | 観点 |
|------|------|
| □ バックエンドを起動（`AGENTS.md` の env・Mongo・必要なダミー値） | 起動時に例外で落ちない |
| □ Discord Bot がオンライン | 想定サーバーに接続済み |
| □ Twitter 関連（Webhook・ポーリング・鍵）が意図どおり有効/無効 | 二重応答の原因にならないか確認 |
| □ ログ出力先を把握（コンソール / ファイル） | `[Webhook]`・`[Twitter Reply]`・`LLM` 周りが追える |
| □ （任意）ダッシュボードや DB で会話履歴を確認できる | メモリ・スレッドの取り違えを疑うときに使う |

## 1. Twitter（X）

### 1.1 Webhook・受信経路

| # | 作業内容 | 見る観点 |
|---|----------|----------|
| 1 | □ プロバイダ側で Webhook URL 検証（GET）が通る | 200・設定が保存される |
| 2 | □ テスト用に **メンション or ルール一致** のツイートを投稿 | サーバに POST が届く（ログ `[Webhook] Twitter webhook 受信`） |
| 3 | □ `X-API-Key` 誤りのリクエストを意図的に流す（検証環境のみ） | 401・本番鍵が漏れていないこと |

### 1.2 リプライ・会話

| # | 作業内容 | 見る観点 |
|---|----------|----------|
| 4 | □ ボットに **1段のリプライ** | 返信が1通・内容が文脈と整合 |
| 5 | □ **スレッドを数往復**（返信に返信） | 親ツイートの取り違えがない（ログのスレッド件数と実ツイート） |
| 6 | □ **自分（ボット）のツイートへのリプ** | 仕様どおり無視／応答するか（運用ポリシーと一致） |
| 7 | □ **同一ツイート ID** が Webhook とポーリングの両方に来る状況を意識 | 二重返信が起きない（処理済み ID） |

### 1.3 引用 RT・いいね

| # | 作業内容 | 見る観点 |
|---|----------|----------|
| 8 | □ `quote-rt` 系ルールで引用 RT を発生させる | ログに引用検知・必要ならいいね・返信イベント |
| 9 | □ **日次返信上限到達** に近い状態（またはテストで上限を再現） | 上限時は返信スキップ・ログに理由が出る |

### 1.4 定期・その他 Twitter

| # | 作業内容 | 見る観点 |
|---|----------|----------|
| 10 | □ （利用中なら）定期投稿・自動ツイート系 | 時刻・重複・内容の破綻がない |
| 11 | □ メンバー向けツイート応答（運用している場合） | 通常リプライと経路・トーンが混ざらない |

## 2. Discord

### 2.1 テキスト（ギルド）

| # | 作業内容 | 見る観点 |
|---|----------|----------|
| 12 | □ 監視対象チャンネルで **短い指示**（例：挨拶・事実質問） | 応答がチャンネルに返る・別チャンネルに流れない |

## 4. ログで押さえるキーワード（見ながら確認）

改修後に目視しやすい文字列の例（実装に依存するため、見つからなければ grep で更新する）。

- Twitter: `[Webhook]`、`llm:post_twitter_reply`、スレッド取得失敗の warn
- Discord: `llm:get_discord_message`、ギルド名・チャンネル ID が想定と一致するか
- 共通: `LLM処理エラー`、未処理の Promise rejection が増えていないか
